### 2026-09-04 (14:41 EDT)

- **Fixed the CI build failure on the PR:** `next build` tries to statically pre-render every page it can at build time, which meant it was actually attempting to run `getRatesBundle()` -- a real Supabase call -- during the build itself. CI correctly has no `.env.local` (never committed), so it threw "Missing NEXT_PUBLIC_SUPABASE_URL...". Fix: `export const dynamic = "force-dynamic"` in `src/app/dashboard/page.tsx`. Verified by actually reproducing the CI failure locally first (temporarily moved `.env.local` aside, ran `npm run build`, confirmed it failed the same way) and then confirming the fix (`npm run build` succeeds with zero env vars present, route table correctly shows `/dashboard` as `ƒ (Dynamic)` instead of `○ (Static)`) -- then restored `.env.local` and re-verified the full build/lint/test suite with real credentials too.

- **`validateSelections.ts`:** added always-required checks for the 4 newly-nullable fields; `livingSituation === null` now short-circuits before the on_campus/commuter branching (previously null would have silently fallen through to the on_campus branch) and the parking-eligibility check is skipped entirely while living situation is unanswered -- this is the actual fix for the reported bug.
- **`DEFAULT_SELECTIONS`:** everything nullable now defaults to `null` -- a first-time visitor sees a genuine $0 total and "answer this" prompts, never a combination error.
- **`TuitionPanel.tsx`:** credit hours slider/number input can't natively show "no value," so it renders at a neutral position (12) but visually greyed with a "move the slider..." prompt until the user actually touches it -- `creditHours === null` itself *is* the touched/untouched state, no separate tracking flag or `useEffect` needed.
